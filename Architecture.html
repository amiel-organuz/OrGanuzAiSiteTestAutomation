Playwright automation with Product E2E Matrix, QA orchestration, FastAPI, Scalar, Grafana, Prometheus, Organuz Supabase API tests, and Allure 3

A single-file architecture view for the OrGanuz AI site automation stack. Local runs start the runtime services, execute the Playwright projects, generate Allure 3, and print the main service links. The product project tracks the calculator/property-characterization E2E matrix across personas, roof and polygon types, panel thresholds, quotations, and company access rules. The QA agent can invoke the real Playwright CLI through an orchestrator case mapping, while GitHub Actions runs the core projects in parallel, exercises the Organuz Supabase/PostgREST backend, and publishes Allure to GitHub Pages.

Stack Overview

TS Playwright Tests

Runs marketing UI tests in chromium, product E2E matrix tests in product, and Organuz Supabase/PostgREST backend tests in organuz-api (plus the internal agent orchestrator regression specs).

E2E Product Matrix

tests/product covers 12 main CALC-ROOF scenarios across 4 personas, plus panel-threshold, Ramot, and UI-only no-panel coverage.

PY FastAPI

Provides /health, /metrics, /openapi.json, built-in docs at /docs, and automation metadata under /automation.

API Organuz Backend

The organuz-api project tests the Organuz Supabase/PostgREST backend — the /rest/v1/projects resource and edge-function CORS preflights — using the public anon key.

DOC Scalar API Reference

External Scalar docs read the FastAPI OpenAPI schema from localhost:8000/openapi.json.

MON Prometheus

Scrapes FastAPI metrics from api:8000/metrics through server/prometheus.yml.

MON Grafana

Runs on host port 3001 with a provisioned Prometheus datasource and the OrGanuz QA Dashboard.

REP Allure 3

Generated by the CLI and CI workflow, served locally by Nginx, and published by GitHub Pages on main branches.

FAIL Failure Capture

tests/ui/diagnostics/intentionally-failing.spec.ts is an expected-failure test that verifies screenshots, videos, traces, and Allure attachments.

AGENT QA Orchestrator

Coordinates Azure DevOps, Google Sheets, Playwright, and OneDrive. The CLI-backed runner maps orchestrator cases to real Playwright projects and reports pass/fail evidence back through the agent loop.

Architecture Diagram

QA Agent Orchestrator Stack

The QA Agent Orchestrator coordinates multiple testing tools and integrations to automate the verification pipeline:

Azure DevOps

System of record. The orchestrator reads test plans, writes back outcomes, and files bugs idempotently (guards against duplicates).

Google Sheets

Provides parameterized input/expected values and environment configurations, and logs live results.

Playwright Runner

CliPlaywrightRunner invokes npx playwright test for mapped projects, reads test-results/results.json, and returns normalized execution results to the orchestrator.

OneDrive Store

Durable evidence storage. Returns shareable links that are linked in reported DevOps bugs.

Current Test Mapping

npm run agent:current-tests maps PW-ORGANUZ-API, PW-CHROMIUM, PW-PRODUCT, and PW-AGENT to the real Playwright organuz-api, chromium, product, and agent projects.

Agent Current-Test Flow

1

Build agent

npm run agent:current-tests first compiles TypeScript with tsc -p tsconfig.json.

2

Create suite

run-current-tests.ts creates stubbed ADO/Sheets/OneDrive connectors and a generated suite for the repository's Playwright projects.

3

Run projects

CliPlaywrightRunner executes --project=organuz-api, --project=chromium, --project=product, and --project=agent as orchestrator cases.

4

Report outcome

The orchestrator uploads report artifacts, writes case results, files bugs for failures, logs Sheets rows, and returns a JSON run summary.

CLI Flow

1

Typecheck

npx tsc --noEmit validates the TypeScript framework before tests run.

2

Start stack

The script starts FastAPI, Scalar, Prometheus, and Grafana when local endpoints are not ready.

3

Run tests

npm test executes chromium, product, and organuz-api. The local shell flow runs chromium and organuz-api while service containers are online, then restarts the api container so Grafana picks up fresh results.

4

Serve reports

Allure 3 is generated and served through the local Nginx allure service.

Product E2E Matrix

The product Playwright project is driven by tests/product/matrix/e2e-matrix.data.ts and mirrors the working E2E matrix document.

  • 12 main CALC-ROOF-001 to CALC-ROOF-012 characterization scenarios.
  • 4 personas per main scenario: customer, consultant, company, and company employee.
  • Property types: private house, residential building, commercial, agricultural, and public.
  • Polygon behavior: building, parking, sports court, and mixed building + parking/sports-court flows.
  • Roof and surface types: concrete, tiles, iscoverit, parking, and sports court.
  • Negative coverage for fewer than 5 panels and UI-only tracking for the no-panel case.
  • Live browser flows are gated by PRODUCT_E2E_ENABLED=true and persona credentials.

QA Dashboard Metrics

FastAPI parses test-results/results.json and exposes dashboard-friendly Prometheus metrics. Grafana provisions the OrGanuz QA Dashboard automatically.

  • qa_playwright_tests_total{project,status} for pass/fail/skipped counts.
  • qa_playwright_duration_seconds{project} for project runtime.
  • qa_playwright_last_run_timestamp_seconds for report freshness.
  • qa_playwright_report_present for “latest report loaded” status.

Backend API and Failure Capture

Organuz Supabase API

  • The organuz-api project (tests/organuz-api/**) targets the Organuz Supabase/PostgREST backend.
  • Base URL and public anon key come from config.json → organuzApi (env override ORGANUZ_API_ANON_KEY).
  • Covers the /rest/v1/projects resource: contracts, query behaviours, anon-key auth, and RLS.
  • Edge functions are only exercised through their OPTIONS CORS preflight — tests never POST live email/subscription requests.
  • Suites: contracts/, resources/, security/, and functions/.

Expected Failure Demo

  • tests/ui/diagnostics/intentionally-failing.spec.ts is tagged @intentionally-failing.
  • The test uses test.fail(), so CI stays green when the assertion fails as expected.
  • src/fixtures/index.ts attaches Playwright artifacts to Allure after unexpected failures.
  • Skip the demo with npx playwright test --grep-invert "@intentionally-failing".

GitHub Actions

  • typecheck validates TypeScript.
  • tests runs chromium and organuz-api in a matrix.
  • The repository also has local product and agent Playwright projects. Run them directly or through agent:current-tests.
  • Test files are grouped by subject: UI homepage/content/flows/diagnostics, Organuz backend API contracts/resources/security/functions, product matrix/flows/smoke/support, and agent orchestrator coverage.
  • services-smoke starts FastAPI, Scalar, Prometheus, and Grafana.
  • publish-allure merges Allure artifacts and generates Allure 3.
  • deploy-allure publishes the report to GitHub Pages on main or master.
  • report-summary writes Allure, FastAPI, Scalar, and Grafana links into the Actions summary.
